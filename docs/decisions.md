# 决策背景

以下记录已确认的需求背景和设计取舍，供后续修改时理解约束。当前行为以源码为准；早期方案中的未落地建议不构成实现要求。

## 范围与工程约束

用户最初要求统一书架、多标签阅读，明确不做分类、筛选、搜索，并限定采用 gpui-pdf 与 rbook。后续明确要求遵循操作系统应用数据目录惯例、工具栏优先使用图标，以及测试编排全部使用 Python 标准库。这些是产品和协作边界，不应从已有代码里“缺少某功能”反推。

当时选择受控原生 EPUB 重排，是因为解析库并不提供完整阅读排版；任意出版社 CSS 保真不作为承诺。接入 PDF 时遇到 GPUI 类型兼容和位置恢复接口缺口，因此选择仓库内补丁，避免修改 Cargo 全局缓存。后续升级应重新验证这些问题是否仍存在，历史兼容问题不是永久禁止升级的理由。

核对实现：[Cargo.toml](../Cargo.toml)、[EPUB](../crates/runtime/src/epub.rs)、[PDF 补丁来源](../vendor/gpui-pdf/PATCHES.md)。

## 书架操作入口

用户分别要求列表改为可调整列宽的二维表格、将操作移到行右键菜单，以及卡片右下角使用省略号菜单。这解释了两种布局的不同入口；修改时应同时考虑两种使用路径。

列表需求称为“出版年月”，但当时数据只有年份，因此选择保留真实精度，不补造月份。表头名称不能作为元数据精度的依据。

当前菜单文案和交互以 [书架实现](../src/shelf.rs) 为准。
